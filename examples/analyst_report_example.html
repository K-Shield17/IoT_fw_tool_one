Priority Security Cases

P1Sensitive key material is broadly readable

/etc/ssl/server.key
Risk: HIGHConfidence: HIGH

Why this matters

Sensitive SSH/TLS key material is present and the extracted filesystem mode (644) allows group or other users to read it. This can expose cryptographic identity or authentication material to unintended local principals.

Attack scenario

Local or compromised process reads the key file → key material is copied → attacker may impersonate the device/service or reuse authentication material depending on the key purpose.

Potential impact

  • Private key disclosure
  • Service/device impersonation
  • Unauthorized authentication depending on key usage

Recommended remediation

  1. Restrict key permissions to the owning service/account
  2. Rotate exposed keys
  3. Avoid shipping shared private keys across devices
  4. Use device-unique key provisioning where possible
Evidence chain
  • Sensitive key material detected
  • Filesystem mode: 644

P2Weak Unix-MD5 password hashes present

Credential stores
Risk: HIGHConfidence: HIGH

Why this matters

Unix-MD5 ($1$) password hashes were identified in 2 firmware file(s). MD5-crypt provides substantially weaker password-hash resistance than modern password hashing schemes and increases offline cracking risk if the credential store is obtained.

Attack scenario

Attacker obtains the firmware or credential store → extracts MD5-crypt hashes → performs offline password cracking → recovered credentials may enable device access where the corresponding accounts are active.

Potential impact

  • Offline credential cracking
  • Unauthorized account access if a password is recovered
  • Credential reuse risk

Recommended remediation

  1. Replace MD5-crypt with a modern password hashing scheme supported by the platform
  2. Use unique high-entropy credentials
  3. Remove default or embedded accounts where unnecessary
  4. Rotate credentials after remediation
Evidence chain
  • Unix-MD5 ($1$) hash format detected
  • Affected files: /etc/passwd, /etc/shadow

P3Embedded web service with weak exploit mitigations

/usr/sbin/httpd
Risk: HIGHConfidence: MEDIUM

Why this matters

The firmware contains /usr/sbin/httpd, identified as a web management/service component. Multiple exploit mitigations are absent or incomplete. These observations do not by themselves prove an exploitable memory-corruption vulnerability; they indicate that exploitation may be easier if such a flaw exists.

Attack scenario

Network or protocol input reaches the service → a memory-safety flaw is triggered (if present) → missing mitigations reduce exploit resistance → service compromise or code execution may become more feasible.

Potential impact

  • Potential service compromise
  • Potential arbitrary code execution if a memory-safety vulnerability exists
  • Possible foothold for further system compromise

Recommended remediation

  1. Update the affected service to a maintained version
  2. Enable stack protector where supported
  3. Enable PIE
  4. Enable Full RELRO
  5. Ensure NX is enabled
  6. Restrict unnecessary network exposure
  7. Review externally reachable input-processing code
Evidence chain
  • Role: web_server
  • Startup/config reference: false
  • RELRO: No RELRO
  • Stack Canary: No Canary Found
  • NX: NX enabled
  • PIE: PIE Disabled
  • FORTIFY: No
